Environment Setup

How Headtilts manages configuration across development, staging, and production.

.env files Three environments Switch script Docker + native dev

File Map

All environment files live at the monorepo root. The API reads the root .env via --env-file=../../.env; Docker Compose reads it natively.

Headtilts/
├── .env # ← active config (gitignored — never commit)
├── .env.dev # development template (tracked)
├── .env.staging # staging template (tracked)
├── .env.prod # production template (tracked)
├── .env.example # full variable reference (tracked)
├── .env.docker # legacy Docker template (kept for reference)
├── scripts/
│ └── switch-env.sh # copies a template → .env
├── apps/
│ ├── api/
│ │ └── .env.example # API-specific subset (reference only)
│ ├── admin/
│ │ └── .env.example # VITE_API_URL only
│ └── web/
│ └── .env.example # VITE_API_URL + VITE_SITE_NAME
Rule: The root .env is the single source of truth for all services. Sub-package .env.example files document package-specific variables but are not loaded at runtime.

Three Environments

Development
.env.dev
Local machine. Weak secrets, localhost URLs, MailHog for email. Suitable for native pnpm dev or Docker on port 8080.
Staging
.env.staging
Server mirror of production. Unique credentials and a real domain. Used to validate builds before production promotion.
Production
.env.prod
Live server. Strong random secrets, real domain, real SMTP. File has permissions 600. Never use dev or staging secrets here.

Quick Start — Native pnpm Dev

  1. Copy the dev template 
    cp .env.dev .env
# or use the switch script:
./scripts/switch-env.sh dev
  2. Verify MySQL is running locally 
    # Create the database if it doesn't exist
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS headtilts;
  CREATE USER IF NOT EXISTS 'headtilts'@'localhost' IDENTIFIED BY 'headtilts';
  GRANT ALL ON headtilts.* TO 'headtilts'@'localhost';"
  3. Install dependencies and run migrations 
    pnpm install
cd apps/api && pnpm prisma migrate deploy && pnpm prisma db seed
  4. Start all services 
    pnpm dev

    Web: http://localhost:5173 · Admin: http://localhost:5173/admin · API: http://localhost:3000

Quick Start — Docker Compose Dev

  1. Copy the dev template and set Docker-specific values 
    ./scripts/switch-env.sh dev
# Then open .env and uncomment the Docker URL lines:
#   SITE_URL=http://localhost:8080
#   WEB_URL=http://localhost:8080
#   ADMIN_URL=http://localhost:8080/admin
#   VITE_API_URL=/api
  2. Build and start containers 
    docker compose up -d --build
  3. Seed the database (first run only) 
    docker compose exec api sh -c "cd apps/api && node_modules/.bin/prisma db seed"
  4. Open the app

    Everything on http://localhost:8080 (or whatever HTTP_PORT you set).

The Switch-Env Script

scripts/switch-env.sh copies a named template to .env, backs up the existing file, and warns about any unfilled CHANGE_ME placeholders.

# Show current environment
./scripts/switch-env.sh

# Switch to a different environment
./scripts/switch-env.sh dev
./scripts/switch-env.sh staging
./scripts/switch-env.sh prod

The script backs up the existing .env as .env.backup.YYYYMMDD_HHMMSS before overwriting, so you never lose the previous configuration.

Tip: After switching to staging or prod, the script prints every line that still contains CHANGE_ME so you know exactly what to fill in.

Variable Reference

All variables are listed here with their allowed values and which environments require them.

Database

VariableRequiredDescriptionDev default
DATABASE_URL Required Prisma MySQL connection string. Host is localhost in native dev; mysql inside Docker Compose. mysql://headtilts:headtilts@localhost:3306/headtilts
MYSQL_DATABASE Docker Database name for the MySQL container. Must match the database in DATABASE_URL. headtilts
MYSQL_USER Docker MySQL application user created by the container. Must match DATABASE_URL. headtilts
MYSQL_ROOT_PASSWORD Docker MySQL root password. Only needed by the container — not exposed to the API. Set a unique value
MYSQL_PASSWORD Docker Password for MYSQL_USER. Must match DATABASE_URL. Set a unique value

JWT

VariableRequiredDescriptionDev default
JWT_SECRET Required Signs access tokens (15 min). Changing it invalidates all active sessions. Weak dev value
JWT_REFRESH_SECRET Required Signs refresh tokens (7 days). Must differ from JWT_SECRET. Weak dev value
JWT_EXPIRES_IN Optional Access token lifetime. Uses ms format: 15m, 1h, etc. 15m
JWT_REFRESH_EXPIRES_IN Optional Refresh token lifetime. 7d

API Server & URLs

VariableRequiredDescriptionDev default
NODE_ENV Required Runtime mode. Controls Express error verbosity and Prisma logging. Values: development | staging | production. development
API_PORT Optional Internal Express port. Not exposed to the host in Docker (nginx proxies to it). 3000
SITE_URL Required Canonical site URL. Used in email links, canonical tags, and sitemap. No trailing slash. http://localhost:5173
WEB_URL Required Public website URL. Used in CORS allow-list and redirects. http://localhost:5173
ADMIN_URL Required Admin panel URL. Typically SITE_URL/admin. http://localhost:5173/admin
VITE_API_URL Required Build-time URL injected into the React bundles. Use a relative path (/api) when nginx is in front; absolute (http://localhost:3000/api) for native dev without nginx. http://localhost:3000/api

File Uploads

VariableRequiredDescriptionDev default
UPLOAD_DIR Optional Directory where uploaded files and generated image variants are stored. Relative to the apps/api package root in native dev; absolute inside Docker. ./uploads
MAX_UPLOAD_SIZE Optional Maximum file size accepted by Multer. Uses bytes or shorthand: 10mb, 50mb, etc. 10mb

SMTP / Email

All SMTP variables are optional. When SMTP_HOST is empty, email is disabled and all outgoing messages are logged to the API console instead.

VariableDescriptionExample
SMTP_HOSTSMTP server hostname. Leave empty to disable email.smtp.mailgun.org
SMTP_PORTSMTP port. Typically 587 (STARTTLS) or 465 (SSL).587
SMTP_SECUREtrue for port 465 SSL; false for port 587 STARTTLS.false
SMTP_USERSMTP authentication username.postmaster@mg.example.com
SMTP_PASSSMTP authentication password.API key / password
SMTP_FROM"From" address in emails. Quoted format recommended.Headtilts <no-reply@example.com>

Setting Up a Staging Server

  1. Pull the repository on the staging server 
    git clone https://github.com/your-org/headtilts.git /opt/headtilts
cd /opt/headtilts
  2. Copy the staging template 
    cp .env.staging .env
chmod 600 .env
nano .env   # replace every CHANGE_ME value
  3. Generate secrets 
    # Paste output into JWT_SECRET and JWT_REFRESH_SECRET
openssl rand -base64 64
  4. Build and start 
    docker compose up -d --build
docker compose exec api sh -c "cd apps/api && node_modules/.bin/prisma migrate deploy"
docker compose exec api sh -c "cd apps/api && node_modules/.bin/prisma db seed"

Setting Up Production

Follow the same steps as staging, but:

  • Use cp .env.prod .env as the starting point.
  • Generate different secrets from staging — they must never be shared between environments.
  • Set HTTP_PORT=80 if nginx on the host or a load balancer handles HTTPS termination.
  • Set SMTP_HOST to a real transactional mail provider (Mailgun, Postmark, SES, etc.).
Never copy staging JWT_SECRET or database credentials to production. Generate fresh secrets for each environment.

Pre-go-live checklist

  • NODE_ENV=production
  • JWT_SECRET and JWT_REFRESH_SECRET are unique 64+ character random strings
  • Database password is strong and not shared with staging/dev
  • SITE_URL, WEB_URL, ADMIN_URL point to your live domain with correct protocol (https://)
  • VITE_API_URL=/api (relative — nginx handles routing)
  • SMTP_HOST set to a real SMTP provider
  • .env file permissions are 600: chmod 600 .env
  • No CHANGE_ME placeholders remain: grep CHANGE_ME .env

Generating Strong Secrets

# 64-byte base64 string (recommended for JWT secrets)
openssl rand -base64 64

# 32-byte hex string (alternative)
openssl rand -hex 32

# Example output (do not use these):
# JWT_SECRET=Hk3mXq9...
# JWT_REFRESH_SECRET=Zp7rNw2...

Generate a separate value for JWT_SECRET and JWT_REFRESH_SECRET. Never reuse a secret across environments.

Troubleshooting

API won't connect to MySQL

  • In Docker: host must be mysql (not localhost) in DATABASE_URL.
  • In native dev: host is localhost. Verify MySQL is running: mysql -u headtilts -p headtilts.
  • Check the MySQL container health: docker compose ps — it takes ~30 s to become healthy.

Admin shows wrong API URL

VITE_API_URL is baked into the frontend bundle at build time. After changing it you must rebuild:

docker compose up -d --build admin

Email not sending

  • If SMTP_HOST is empty, email is intentionally disabled — look for log output in the API console.
  • For local testing, start MailHog (docker compose up mailhog) and set SMTP_HOST=localhost SMTP_PORT=1025. MailHog UI: http://localhost:8025.

Sessions invalidated after restart

Changing JWT_SECRET or JWT_REFRESH_SECRET invalidates all existing tokens — users are logged out. This is intentional; rotate secrets only when necessary.

switch-env.sh: permission denied

chmod +x scripts/switch-env.sh
